The SEO plugin's list of pages built in code no longer makes a Next.js build trace the whole
project into the server output. Looking up each route's source file joined the working
directory with the route's name, which Turbopack could not bound, so every source file and
the `public` folder were deployed as server code: slower deploys, and a risk of a host's size
limit. The lookup is now marked for Turbopack to ignore. Where a deployment does not ship its
sources, a route is named by its path under `app`, as it already was where no source file was
found.
