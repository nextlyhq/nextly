A foreign key may only target a table an earlier migration stream creates, a plugin keying to another plugin's table must declare the dependency, a plugin module's keys are judged against its own modules' order at generation and before a run, and a declared check or expression index is refused on a server that cannot hold it, naming its version. A key whose target the app's stream or a later plugin creates was left to the database to refuse at a fresh install; now the declaration is refused, naming the stream. Before a run, a module's key may reach a table the database already holds, such as an installed dependency's or an adopted table. On MySQL before 8.0.16 a declared CHECK parsed and held nothing, and before 8.0.13 an expression index failed to build. Both are now refused at the compile the push and the migration share, and before any migration runs, a pending file or plugin module is judged on what it adds: the constructs its snapshot adds over the one before it, and the statements it would run, so a hand-written file with no snapshot is judged too.
