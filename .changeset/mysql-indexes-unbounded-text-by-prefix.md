On MySQL, a text, textarea or rich-text field with `index: true` and no `maxLength` is indexed by its first 191 characters on every road. A component (field group), a custom user field, a migration file that adds the index, and the development push adding an indexed field to an existing table each wrote a whole-column index on the TEXT column, which MySQL refuses ("BLOB/TEXT column used in key specification without a key length"), so the save or migration failed. Collections and new tables already used the prefix; every road now writes it from the same rule, which also covers the other TEXT and BLOB sizes. PostgreSQL and SQLite still index the whole value, and a unique index is unchanged.
