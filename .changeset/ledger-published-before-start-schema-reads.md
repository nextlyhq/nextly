A production start that does not run migrations at start publishes the cache tag expiry ledger as soon as it has checked the database is set up, before it reads the schema, the field-group storage names and the plugins' install states. A stored page, the admin's included, waits for the ledger before it is served, so it no longer waits for those reads: on a database 100 ms away the admin page's first byte came about 1.3 s after the server's first answer, and now about 0.55 s. A start that runs migrations at start still publishes it after them, as they record their own expiries.
