A route handler that caught an error now answers with that error on a host whose function bundle lacks part of `next/navigation`. Nextly loads Next's `unstable_rethrow` lazily, which file tracing cannot follow, so on such a bundle (seen on Vercel with Next 16.4) loading it failed and turned the original error, such as a database timeout, into a 500 of its own after the request had already failed. Where it cannot be loaded, Nextly now makes the same check from the errors' digests, so a `redirect()` or `notFound()` still passes through and every other error gets its own response.
