The public `Nextly` SDK object every consumer's app imports was assembled by
hand in two places — the normal `getNextly({ config })` path and the fallback
for services registered directly — and the two copies had already drifted:
shutting down a fallback-built instance was silent where the factory-built one
logged "Nextly shutdown complete". Both paths now build the instance through
one function, so the object a consumer receives cannot differ by which path
constructed it; the fallback's shutdown now logs the completion line like the
factory's always has. No method, member, or behaviour of the SDK surface
changed.
