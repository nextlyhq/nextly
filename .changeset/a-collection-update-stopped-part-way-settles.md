A collection update whose development push stops part way, on MySQL or on SQLite, is now settled to what of it the database holds, as a collection's Builder apply already is. The update's migration file and snapshot are replaced by one holding exactly the changes that landed, recorded applied, and the collection's registry row records those fields as applied. This server's running shape is brought to them, and the update answers the failure naming each change it asked for as applied or not. It used to keep its files for `nextly migrate:resolve` and leave the row on the fields from before the save.
