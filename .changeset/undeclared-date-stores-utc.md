A `Date` written inside a transaction to a column the table model does not declare now stores the same instant as one written to a declared date column. On PostgreSQL it was bound by node-postgres in the app server's own time zone, and a `timestamp` column drops the offset, so on a server not running in UTC the value was stored shifted by the server's offset. Each adapter now spells such a `Date` as its date field columns do. MySQL (since its sessions were pinned to UTC) and SQLite already stored the right instant and are unchanged. Rows written that way before this release keep their shifted value: on PostgreSQL with a server not in UTC, a date written through an undeclared key inside a transaction may need checking.
