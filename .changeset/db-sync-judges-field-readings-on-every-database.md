`nextly db:sync` and the development push now judge a column's type change by what the new field reads from each value on PostgreSQL and MySQL too, as they already did on SQLite, keeping the worse of that verdict and the column's own rule. On MySQL, a text becoming a unique field whose values the column's collation holds as one ("a@b.co" and "A@b.co") is now refused before anything runs, naming the rows; before, it was judged safe. Changes the column's rule already refused on PostgreSQL and MySQL stay refused.
