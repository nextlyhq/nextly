A Single schema save that renames a field onto a column the table already has is refused
before any statement runs, with `RENAME_TARGET_TAKEN` naming the table and both columns, on
every dialect. This holds for a translated field's companion table too. Before, on MySQL, the
database's "Duplicate column name" was passed over as a step an earlier run had made: the
registry recorded the new name while every value stayed in the old column.

A rename statement the database refuses is now always a failure, never a step already
applied. A save that finishes a rename an earlier stopped save already made goes through, as
before.
