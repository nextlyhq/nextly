A plugin's schedules now run. `contributes.schedules` takes `{ slug, cron, job, tz?, input? }`: each call to the jobs route enqueues the named job once for the schedule's latest cron window, in the schedule's time zone, even after that job has finished and with several callers at once. A schedule's first job is for the first window after it is first seen, and missed windows are not run later. A schedule that cannot run stops start-up, naming the plugin. Windows are recorded in a new core table, `nextly_schedule_windows`, which `nextly migrate` creates on existing installs, and are kept for 30 days.
