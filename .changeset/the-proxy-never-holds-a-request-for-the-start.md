The site's Proxy (`createNextlyProxy`) no longer holds a request while Nextly starts. Before, every request it matched waited for the whole start before the plugins' proxy handlers ran, including pages, files from `public/` and the prebuilt admin page. Against a database far from the server, that meant nothing was served for over a minute after a cold start.

Now, while a start is under way, the Proxy lets each request through as the page alone, and begins the start if nothing has. Plugins' handlers apply from the first request after the start finishes. A redirect or header that must hold from a server's very first request belongs in `next.config`.
