`nextly migrate` applies an upgrade to a database whose field groups moved to the current names when the migration history records no field group, rather than refusing it as behind the storage, and `migrate:create --field-group-names=current` is written beside other pending changes when there is nothing to rename. `nextly migrate:resolve --rolled-back` now reaches migrations an early release recorded without `.sql`, so `nextly migrate:baseline` can adopt such a database; its refusal names that step, and `nextly migrate` reports a registry row left by an entity the configuration no longer declares apart from tables still to migrate.
