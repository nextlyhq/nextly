A Schema Builder dialog save that runs its own migration file asks what the push asks before it changes anything. A rename the request does not answer, or a field it removes whose column holds values without confirming the drop, refuses the save with nothing written, as the push refuses it, rather than the file dropping the column's values. The admin's dialog answers each rename it shows and confirms each removed field, so the Builder works as before. An API client that applies a collection's, a Single's or a field group's schema through the dialog's apply must now answer each rename and confirm each drop.
