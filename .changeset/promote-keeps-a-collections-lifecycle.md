`nextly db:sync --promote` prints every collection-level option a Schema Builder collection stores that changes how it behaves, not only its slug and fields. A collection with Draft/Published is printed with `status: true` (and `versions: false` where it keeps no history, since in code `status: true` alone turns history on), so once promoted its drafts stay unpublished and off its public pages. Its drafts and history settings, translations, `timestamps: false`, cache and webhook opt-outs, indexes, and a table name code would derive differently (`dbName`) are printed too, each spelled so that the code-first sync stores it back as the value the collection had.
