`nextly migrate` now lets go of the inline `UNIQUE` an earlier release's Schema Builder wrote into a one-to-one relationship's column, once that relationship has been edited into a many-to-one and its change applied, so the column takes repeats on PostgreSQL and MySQL. Only the exact constraint that release made is dropped (PostgreSQL's `<table>_<column>_key`, MySQL's single-column index named after the column, while another index still serves the foreign key), and only on a Schema Builder collection or Single whose change has reached the database; every other unique index stays. SQLite keeps the inline `UNIQUE` for now.
