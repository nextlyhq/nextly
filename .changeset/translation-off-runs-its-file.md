In development, a Schema Builder save that turns a Single's or field group's translation off now runs its own migration file instead of the dialog's push, when it changes nothing else: the file puts each translated column back on the main table as the migration history records it, Required and Unique settings included, keeps the default language's values there and archives the others. A save that turns translation off and also changes the fields or Draft/Published still uses the push, since `nextly migrate:create` would refuse to write that change as files.
