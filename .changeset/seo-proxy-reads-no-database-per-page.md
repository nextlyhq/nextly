The SEO plugin's Proxy no longer reads the database for a page request no redirect is for: each server keeps the addresses redirects hold in memory, so a static or CDN-served site can wire `proxy.ts` without a database read per page. A saved redirect applies at once on the server that saved it and within 15 seconds elsewhere. With `NEXTLY_PRODUCTION_ADDRESSES` set, the staging guard reads only the environment. The Proxy now notes that it runs, so SEO › Problems lists "Redirects saved but not served" when redirects are saved and `proxy.ts` is not wired, and `/proxy-status` says whether it runs.
