Collection events (`collection.<slug>.created`, `.updated` and `.deleted`) now arrive when the write commits, before its `afterCreate` / `afterUpdate` / `afterDelete` hooks rather than after them: a listener that relied on the after-hooks having run should do that work in an `after*` hook instead. A write made inside a caller's transaction (`createEntryInTransaction`, `updateEntryInTransaction`, `deleteEntryInTransaction`), and each entry of `createEntries`, `updateEntries` and `deleteEntries`, now sends its collection event too: once the outermost transaction commits, after the after-hooks it runs inside that transaction, and never if the transaction rolls back.
