A plugin can now expire the cached pages built from its own data. `ctx.cache.tag(part)` names the tag a read of the plugin's settings or other data carries, and `ctx.cache.expire(...parts)` clears every cached read carrying it, on every instance that shares the database, as a content write does for content. A plugin names and expires only its own tags (`nextly:@plugin:{plugin}:{part}`), never a collection's, a Single's or another plugin's. `pluginCacheTag` from `@nextlyhq/plugin-sdk` spells the same tag for code outside the plugin's context. Both are `@experimental`.
