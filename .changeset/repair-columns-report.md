A new `nextly repair-columns` command reports every column whose type or nullability differs from its field, on the tables Nextly builds from field definitions (collections, Singles, field groups, user fields and their translation tables). Each column is judged against its field as the database last had it applied: a missing table or column is reported as not migrated, a change the configuration holds and no migration has applied as pending, and a plugin's column with the plugin named. Where it can, it says why a column differs: created before a named release, or by a generator that still creates it. It changes nothing in the database.
