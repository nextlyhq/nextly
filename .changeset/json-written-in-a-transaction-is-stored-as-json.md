A JSON value written inside a transaction is now stored as JSON on MySQL. A transaction's `insert` and `insertMany` handed an object or an array to the driver as it was, so MySQL refused the row or stored `[object Object]`, and on PostgreSQL an array was refused as invalid JSON. They now serialize a JSON column's value as the ordinary `insert` does, on every dialect; SQLite, `update` and `upsert` were already correct and are unchanged.
