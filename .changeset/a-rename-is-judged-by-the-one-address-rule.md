Renaming a collection or a Single onto an address whose snake_case form another collection
or Single already holds is refused with `SLUG_SAME_SNAKE_CASE`, as creating one already was:
`team-updates` beside `team_updates` reads as one address. A collection rename is now judged
by the same address rule every other road applies (reserved names, routes, a taken slug and a
same snake_case form), where before it compared the exact slug alone and threw a plain error.

A rename now judges its new address inside the schema lock, so a collection or Single created
or renamed onto the same form at the same moment is seen and refused, rather than both
succeeding.
