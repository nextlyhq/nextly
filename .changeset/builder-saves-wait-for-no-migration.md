Every Schema Builder save now holds the schema lock, and while a migration holds it the save is refused at once with nothing changed, telling the editor a migration is running and to save again once it ends. That covers collection create, update, delete and confirmed apply, a Single's confirmed apply, user-field create, update and delete, and the published collection, Single and user-field schema routes. Before, these saves could run beside `nextly migrate`, `db:sync` or a field-group migration. A save in production takes the lock wherever its table exists and never creates that table, so a database role without DDL rights keeps saving as before; a development save may create it.
