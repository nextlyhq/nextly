Consume password-reset tokens atomically on write to ensure a reset token can only set a password once.

When a password reset is requested, the token is now marked used conditionally within the same transaction that updates the user credentials. Concurrent requests attempting to use the same token result in exactly one successful password update, while subsequent or racing requests are refused without changing credentials.
