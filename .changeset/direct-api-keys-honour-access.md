The Direct API's `apiKeys` namespace honours `overrideAccess: false`, set on the call or on the instance, as the admin's API key routes do. The `user` needs the matching `api-keys` permission, a key is created only for that user, `update` and `revoke` reach only their own keys, and only a super-admin lists or reads other people's keys. Making or changing keys as an API key is refused, and a checked call that names no `user` is refused with `AUTH_REQUIRED`.

Compatibility: only calls that ask to be checked change. Trusted calls, the default, behave as before.
