A collection schema change that fails part way in development now keeps its migration files. On MySQL and SQLite the statements a push ran before a failure stay applied; the save used to remove its files anyway, leaving a change in the database that no file recorded. The files are now kept and left unapplied, and the error says the database holds part of the change, names the files, and says how to finish it (`nextly migrate:resolve --applied`) or reverse it and run `nextly migrate`. A PostgreSQL push, which rolls back whole, still leaves nothing.
