Making a field required, or renaming one, on MySQL now migrates with the right checks. `nextly migrate:create` writes these changes as a prepared statement built from the live column, and `nextly migrate` used to read that as a statement that could delete anything: it refused unless you passed a blanket `--accept-data-loss`, and it never checked for rows with no value before making the column required. `nextly migrate` now reads the prepared statement as the change it makes. A rename needs no consent. Making a column required asks consent for that column only (`--accept-data-loss=<table>.<column>`), and is refused before anything runs while any row holds no value in it.
