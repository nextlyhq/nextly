A visitor, a checked call with no signed-in user, is judged by the Public role: it reads, creates, updates or deletes where the Public role holds the permission and the target's rule, if it declares one, answers `true`, and a rule reading the caller's permissions sees the Public role's. Without the permission a visitor is refused as needing sign-in, and a rule that refuses it as not allowed; the status a caller sees is unchanged. A visitor reads published content only, whatever it asks for, and media through the Public role's `read-media`. `createTestNextly` takes `seedPublic: true` to run the boot's seeding, for tests that need the Public role.
