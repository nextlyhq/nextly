`nextly migrate` now drops a translations table an older PostgreSQL delete left standing, under the data-loss consent. Before deletes dropped the translations table, PostgreSQL dropped the entity's table with `CASCADE`, which removed only the translations table's key to it and left the table, with every translation in it. Each such table is listed with the run's other deletions, named for the entity it belonged to, and dropped only if the consent covers it (by its own name, by the deleted entity's table, or without targets); otherwise the run is refused before anything changes. A table is taken for one only where the history recorded its entity's table under that name and it holds `_parent` and `_locale`.
