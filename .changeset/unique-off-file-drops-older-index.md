A field that stops being unique now stops being unique wherever its migration file runs. Where the database `nextly migrate:create` reads holds the column unique under a second index Nextly did not name (for example an older `posts_code_key`), the file drops that index too, by name and only where it exists, and `migrate:create` says which index it drops. Previously the file dropped only Nextly's own index, and the column stayed unique on every database the file ran on.
