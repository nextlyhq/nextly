`nextly/translation-filter-states` publishes the translation states the translations API accepts (`TRANSLATION_FILTER_STATES` and `TranslationFilterState`) from a module with no server dependencies, so a client can import the list instead of restating it. The admin translation worklist now derives its filter tabs and the state it sends from that list, so a state the server stops accepting can no longer stay on offer and answer with an empty worklist.
