A start that changes no table leaves a changed collection or field group pending, as it already left a changed Single. Before, a start under `test`, with `NODE_ENV` unset, or in development with `NEXTLY_DISABLE_BOOT_APPLY=1` marked the definition applied over a table that does not have its new columns, so the registry said the tables matched a definition they did not. A field group whose only change is help text, or whose table pointer is repaired, keeps its status, as a collection does. A row an earlier start already left applied is brought back in line by `nextly migrate:create` then `nextly migrate`.
