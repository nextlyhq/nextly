`nextly migrate` settles a Builder save left part-way before its run, as a development start does, and judges a save made outside development by its files: complete files run, and a save stopped before its definition was written has its own unapplied files withdrawn. A file the database has applied is never removed. What cannot be settled refuses the run before its first file. A production start that runs migrations settles nothing: it refuses while a save is left part-way, removing no file and leaving `ui-schema.json` as it is. `migrate:check`, `migrate:create` and `db:sync` refuse while such a save stands, and every refusal names `nextly migrate` as a way to settle it.
