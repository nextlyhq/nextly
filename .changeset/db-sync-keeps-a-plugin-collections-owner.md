`nextly db:sync` records a plugin's collections as the plugin's again. In 0.0.2-alpha.81 each `db:sync`, and each re-sync of its watch, recorded them as the app's own, so once the plugin left the configuration, `db:sync --remove-orphaned` listed its tables for deletion. If you ran `db:sync` on alpha.81 with a plugin that adds collections, run `nextly db:sync` once on this release while the plugin is still configured. If you have already removed the plugin, do not run `--remove-orphaned`: put the plugin back, run `nextly db:sync` once, then remove it.
