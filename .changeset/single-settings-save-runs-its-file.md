A Single's schema change through the API now runs its own migration file in development, like the Builder dialog, wherever the change moves no values: a rename keeps every other property of its column on every dialect. A save that does move values (translation turned on or off, a field joining or leaving translation, a field filling the Single's row, or a change reaching a relationship's storage) keeps the service's own statements. A Single API save over an index or column made by hand in its table is now refused as drift, with nothing changed.
