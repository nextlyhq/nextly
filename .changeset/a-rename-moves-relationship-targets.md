Renaming a collection now takes the relationships that point at it along: every relationship stored in a collection, Single or field group the Schema Builder made, nested ones included, points at the new name, in the same step as the rename. A rename is refused, naming the fields, while a relationship that can point at several collections lists it, while a relationship defined in code points at it, or while a relationship already points at the new name. A renamed collection keeps its table, and a key to it, added or changed later, references that table. A schema the rename rewrote moves to a new version, so an editor still holding it from before the rename cannot save the old target back.
