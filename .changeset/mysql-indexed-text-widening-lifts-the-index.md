On MySQL, `migrate:create` now widens a text column an earlier migration made `varchar(255)` and indexed whole: the migration drops the index, changes the column to `TEXT`, and creates the index again keyed by the first 191 characters, as the Schema Builder keys a `TEXT` column, keeping every value. Its DOWN does the same in reverse. Before, the command refused this change. A unique index is still refused, since a unique index by prefix would no longer hold whole values unique: give the field a `maxLength`, or turn Unique off. So is a table whose snapshot predates recording indexes.
