On MySQL, a batch update now judges each entry it publishes on the components and many-to-many relationships stored once it locks that entry, as on PostgreSQL and SQLite. The batch ran at MySQL's default REPEATABLE READ, so an entry later in the batch was read as it stood at the batch's first read: a change another writer committed in between was missed, and the batch could publish a document whose required relationship had been removed. The batch's transaction now reads committed data on every dialect. `updateEntriesInTransaction` runs in the caller's transaction: on MySQL, open it with `{ isolationLevel: "read committed" }` for the same behaviour.
