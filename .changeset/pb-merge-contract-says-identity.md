The published contract for `resolveSiteStyle` said tokens merge by name; they merge by identity.

The merge moved to `tokenIdentity` while the exported JSDoc kept promising the
old key. That text ships in `dist/index.d.ts` for a function exported from the
package root, so a consumer reading the published contract would expect a
same-name stored token with a different identity to replace its config
counterpart, when the implementation keeps both.
