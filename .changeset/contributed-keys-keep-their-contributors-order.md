A key one owner adds to another owner's table is judged by the contributor's migration stream, so a plugin that keys a dependency's table to one of its own tables starts again instead of being refused. Before a run, a plugin module's key may reach a table the database already holds, such as an installed dependency's or an adopted table, and is refused, naming the module and the key, when its target neither exists nor comes from an earlier stream. A pending migration file or plugin module is judged against the server's limits on what it adds: the checks and expression indexes its snapshot adds over the one before it, its own contributions only on another owner's table, and the statements it would run, so a hand-written file with no snapshot is judged too, and a construct an earlier file added no longer refuses an unrelated later one.
