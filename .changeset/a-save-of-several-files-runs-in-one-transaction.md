A Schema Builder save written as several migration files (a change and its translations table's, say) runs them in one transaction on SQLite and PostgreSQL, so a later file's failure takes the earlier ones back with it: nothing of the save stays applied, its files are withdrawn and the definition stands as it was, and the failure names the file the database refused. On MySQL, which commits each schema statement as it runs, the files still run one by one, and a later file's failure now says the database holds part of the change, naming the files kept and not recorded and what to run next.
