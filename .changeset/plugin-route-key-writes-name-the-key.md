A plugin route's write made with an API key is now recorded as the key, not
the key's owner, as a REST write by the same key is. When a route writes through
`ctx.services.collections` as the request's own user (`{ as: "user", user: ctx.user }`),
the entry's content events, its history, the webhook outbox and the activity log name
the API key itself. A session's write still names the person. A write a route makes
as the system, or as another user, is recorded as before. A plugin still cannot name
whom a write is attributed to, and how a key's write is judged is unchanged.
