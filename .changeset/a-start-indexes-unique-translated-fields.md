A unique text field is unique again on a database a start set up. Every
installation keeps its text fields in each entity's translations table, and a
start that made that table (a fresh development database, a plugin's
collection, a code-first Single, component or field group) made it without the
per-language unique indexes `nextly migrate` makes, so two entries could share
a unique slug. The start now makes them, as the development reload already
did. A value already held twice is left without its index and named in a
warning, and the start goes on; nothing stored changes.
