A field renamed and made required, or given a new default, in one change now keeps that change in the migration `nextly migrate:create` writes, on every database. On MySQL, a column made required or renamed by a migration keeps its comment, character set, collation and the checks that use it; on SQLite, a migration that would rebuild a table holding a collation or an index the schema does not record is refused with a message saying so, rather than dropping it. Making a field required no longer stops `migrate:create` on MySQL or SQLite with a request to write the migration by hand.
