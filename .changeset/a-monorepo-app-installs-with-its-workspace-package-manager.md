Adding Nextly to an app inside a monorepo now installs with the workspace's package manager. The generator reads the nearest lockfile, or `pnpm-workspace.yaml` before the workspace's first install, from the app up to its repository's root, so an app in a pnpm workspace no longer gets `npm install` from an `npx` launch. A lockfile above the repository is never taken for the app's. When the app already approves a specific esbuild version in pnpm's settings, that rule is kept, and the generator's note says to approve the version pnpm names if the install then stops on another one.
