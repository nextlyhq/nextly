A migration file that turns translation off now puts each translated column back on the main table as the main table's snapshot records it: its type and its default, and, for a Required field, NOT NULL once its values are back. A Required field one of whose entries has no value in the language kept is refused before the setting, naming the field, and its translations stay. Before, the column went back nullable and the main file that follows was refused as drift on every dialect. On MySQL, a long text field went back as LONGTEXT while the snapshot records `text`, so `nextly migrate` refused the main file that follows as drift, and a Schema Builder save that turned a collection's translation off through its files was refused the same way.
