S3 direct (browser) uploads now store the configured `cacheControl`, as server uploads always did. The pre-signed URL signs it and returns it in `headers` as `Cache-Control`, so the client must send every returned header, and a bucket whose CORS rule lists allowed headers must allow `cache-control`. A collection `prefix` now gives the same key with or without a trailing slash, for server and direct uploads alike: `proofs/` no longer stores server uploads under `proofs//`, and `proofs` no longer stores direct uploads under `proofs2026/`. Files already stored keep their keys.
