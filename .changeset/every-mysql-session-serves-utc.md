Every pooled MySQL connection now pins its session time zone to UTC (`SET SESSION time_zone = '+00:00'`) the moment it connects, so writes, timeseries windows and session-zone comparisons answer the same instants whatever zone the server itself runs in — and a replaced connection is pinned again by the same listener. mysql2's driver-level `timezone` is kept in agreement with the pin: a caller-configured zone that is not UTC is aligned to UTC (with a warning) rather than refused, so a driver parsing in one zone beside a session computing in another can no longer shift values a round-trip fails to cancel. Installations already on UTC servers notice nothing.
