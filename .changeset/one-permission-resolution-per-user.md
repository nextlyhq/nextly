A user's permissions are now resolved once when several of their requests arrive together, instead of once per request. The first admin screen after a server starts, or after the minute a user's resolved permissions are kept for, used to resolve them for every request in flight (up to 18 times over, about 4 statements each); the requests arriving meanwhile now wait for the one resolution under way. A role or permission change made on the same server copy still applies at once to every request after it, since a request never joins a resolution begun before the change, and a resolution that fails refuses every request that waited on it and is not kept.
