`nextly migrate` checks each pending file's renames before the run's first statement: a file that renames a column or a table onto one that is already there, while the one it renames still is, is refused, naming the file, the table and both names, and nothing of the run is applied. Before, the database refused the rename only when it ran, and on MySQL, which commits each schema statement as it runs, the statements of the file before it stayed applied. `migrate --dry-run` names the refusal. A rename after another change to the same table in the run is left to the runner's failure, as before.
