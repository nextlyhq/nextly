`nextly migrate` no longer records an edited collection or single as `applied` on the strength of its table existing. An edit keeps the old physical table, so existence proved nothing about the column, status or localization change the registry row was waiting for. Promotion now also requires the applied migrations to carry the shape the row wants, read from the snapshot paired with each migration and the applied-file ledger. An entity no snapshot describes is promoted exactly as before.
