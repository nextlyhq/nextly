A plugin's `ctx.settings.set` inside its own `ctx.db.transaction` is now refused on every dialect, with an error naming the call and the fix: write the setting after the transaction has finished. Before, it committed on a connection of its own on PostgreSQL and MySQL and survived the transaction's rollback.

This deliberately removes SQLite's former behaviour, where the setting joined the transaction as a savepoint and rolled back with it; a plugin that wrote a setting inside a transaction now writes it after. Outside a transaction a settings write is unchanged.
