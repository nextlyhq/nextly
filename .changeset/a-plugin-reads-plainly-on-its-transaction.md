A plugin's reads on a transaction it holds (`listEntriesInTransaction`, `findEntryByIdInTransaction`, `getSingleInTransaction` and their host forms) take `lock: "none"` (experimental): a plain read on the transaction's connection that takes no row lock on PostgreSQL and MySQL, so a plugin holding a lock of its own can read rows another write is changing without the two waiting on each other until the database refuses one.
