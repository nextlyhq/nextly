A Schema Builder Single now keeps its registry row in a migration when a code-first collection shadows a Builder collection of the same slug. `nextly migrate:create` used to leave out the row of every Builder entity sharing a shadowed slug, of any kind, so the Single's settings change reached the snapshot but not a deployed registry.

`nextly migrate --dry-run --step <n>` now also names a pending Schema Builder file with no snapshot that the step leaves out of the preview. A real run refuses such a file before applying anything, whatever `--step` says.
