A plugin whose schema prefix no longer matches the tables it created now ends a command as `PLUGIN_SCHEMA_PREFIX_CHANGED`, with what changed, why and the declaration that keeps its tables, instead of an unexpected error. `getCachedNextly()` called from work a plugin starts during a boot that `getNextly` did not begin (a request-path boot, or `createTestNextly`) now waits for that boot instead of failing, and the instance `getNextly()` returns carries `rewriteField`, as the Direct API does. `nextly migrate` no longer loads the service registry when the command is imported.
