The SEO plugin's structured data no longer leaves out `dateModified` when the field a content type maps for it, such as a correction date, is empty: it then uses the date the page's content last changed, the same date as its sitemap `<lastmod>`. A date in that field still comes first.

A save that changes only a page's SEO no longer moves its `<lastmod>` and `dateModified` when it sends the page's field groups back unchanged: the ids and dates of the rows a field group is kept in, which such a save rewrites, are no longer read as content. Dates kept by an earlier release stay as they are.
