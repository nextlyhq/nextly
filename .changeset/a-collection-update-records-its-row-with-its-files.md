A collection update whose registry write fails after the update's change has been applied in development now says the change landed part way. It names the kept migration file and the steps that finish it, and leaves no ledger row for that file. The registry row is now written in the same transaction as the ledger rows for the update's files, so the two commit or roll back together. Before, the update answered a generic failure, but its file stayed recorded as applied. A collection service set up without the Builder save writer, which finds its table missing after a change, now answers that the update failed and leaves the registry row as it was. Before, it stored the requested fields as failed under an answer that the update went through.
