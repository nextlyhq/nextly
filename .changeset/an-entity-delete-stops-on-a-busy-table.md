A collection's, a Single's or a field group's delete on PostgreSQL or SQLite no longer waits without end for a table another database session holds. Each try waits as long as `NEXTLY_LOCK_TIMEOUT` allows, and the delete tries again within `NEXTLY_LOCK_TIMEOUT_TOTAL`, then stops with `NEXTLY_TABLE_BUSY` having changed nothing, so deleting again once the holder ends finishes it. On PostgreSQL, a delete next to a field-group table that has no `_parent_table` column no longer fails with an aborted transaction. MySQL deletes step by step, as before.
