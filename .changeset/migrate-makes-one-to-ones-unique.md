`nextly migrate` now makes each one-to-one relationship's column unique where an earlier release left it without its uniqueness: once no file is pending, it checks every such column and, while any repeats a target, adds no index and stops, naming each field and its repeated values (the first 20 per field, every one in the log). A translated one-to-one gets its index per language, on its translations table. A migration file that makes a column unique is checked the same way before any of its statements runs, and a file creating a unique index the database already carries is applied without it, so MySQL no longer fails on the duplicate name.
