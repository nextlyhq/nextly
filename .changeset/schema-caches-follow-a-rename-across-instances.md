A collection renamed or changed on one server instance is now seen by the others within about a second, without a restart. Each instance caches a collection's runtime table by its slug. Before this, another instance kept mapping a renamed collection's old slug to its table, and kept a changed collection's old columns, until it restarted. A rename, a Schema Builder save and a code-first sync that changes a collection's columns now move a shared marker in `nextly_meta`. Each instance checks it at most once a second and rebuilds what it cached, including the table its adapter writes through. No migration is needed.
