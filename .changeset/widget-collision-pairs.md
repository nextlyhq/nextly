A widget registered with an id a plugin also contributes is checked as the one widget the admin draws from the two.

The admin draws such a widget from the registration's query with the registration's settings, or the contribution's where the registration declares none. Each declaration was checked alone, so a pair neither declared could reach the dashboard and fail every request: a registration's ranged query beside a contribution's `limit` setting, or a content setting no knob drives on the registration's source. Startup now checks every such pair once the plugins have registered, and refuses to start naming each widget and its plugin.
