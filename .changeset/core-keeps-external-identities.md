Core keeps each external identity a login provider asserts in its own table: the provider key, the issuer that asserted it where the provider has one, the subject, the address last asserted, and the account that owns the row — and no provider token of any kind. One row per provider key, issuer and subject, with an issuerless provider's rows carrying an empty issuer so the uniqueness holds on PostgreSQL, MySQL and SQLite alike; one subject from two issuers of one key is two identities. A deleted account's identities go with it, in the deletion's own transaction.
