A `contains` filter on a hasMany relationship now works on PostgreSQL. Its ids are stored as a `jsonb` array there, and the case-insensitive match lowered the column, which PostgreSQL refuses for `jsonb` ("function lower(jsonb) does not exist"), so `where: { categories: { contains: id } }` failed while MySQL and SQLite searched the serialized array. The value is now folded as text on PostgreSQL, which also fixes the blog template's category and tag pages there, which listed no posts. A text column matches exactly as before.
