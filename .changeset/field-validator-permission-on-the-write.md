A field type's validator that asks `caller.can` inside a write, such as one
in a field-group instance, is now answered on the write's own transaction.
It was answered on the pool, and once this process's permission version
lapsed during a long write it waited for the connection the write held. On
a small pool it then failed closed, refusing a permitted user's save, which
a retry would let through. The decision itself is unchanged: the same gate
answers it, now with the write's connection threaded through to the
super-admin and permission reads.
