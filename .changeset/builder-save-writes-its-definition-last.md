A Schema Builder save writes its migration files and snapshots first, and the definition file (`db.uiSchemaFile`) last. A save that stops or fails before then leaves the definition exactly as it was, so a later `nextly migrate:create` never reads a change that no migration records, and never writes the save's change again. This holds for collection, Single and field-group saves, the dialog's apply, the push, and the settling of a save that stopped part way. The record that a save is in progress still keeps the definition from before the save.
