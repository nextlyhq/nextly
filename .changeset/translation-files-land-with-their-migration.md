A migration and its translation files are written together. `migrate:create` on a translated collection writes the migration and the files of its translations tables; where one of those could not be written, the migration stayed in the folder without it, and the next `migrate:create` found nothing to write. Every file is now written in full under a temporary name and then put in place in the order `nextly migrate` runs them, so a file that cannot be written leaves the folder as it was. If putting one in place fails once others are there, the command removes the files it had just placed and says the migration was not written.
