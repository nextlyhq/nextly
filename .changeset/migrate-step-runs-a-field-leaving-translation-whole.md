`nextly migrate --step` no longer stops inside a field leaving translation. When the step budget runs out after the move's archive or main file, the run goes on through its shared file and says so, so nothing can write a value into the new shared column between the main file and the copy that fills it. The copy still takes each entry's default-language value, as the Schema Builder and turning translation off do.
