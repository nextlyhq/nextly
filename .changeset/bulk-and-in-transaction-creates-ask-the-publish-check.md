A create that publishes in a batch (`createMany`) or on a caller's transaction (`createEntryInTransaction`) asks the workflow's publish check as an ordinary create does: before any of its hooks, then on its transaction once the entry has its id, settled with the create so a failure keeps nothing of it. With drafts kept by part, the shared part counts as having a pending change only where a pending draft holds shared values, so publishing an approved change to one language no longer asks for a shared approval.
