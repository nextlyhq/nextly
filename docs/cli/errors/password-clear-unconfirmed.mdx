---
title: PASSWORD_CLEAR_UNCONFIRMED
description: "`nextly users:clear-plaintext-passwords --apply` was run without `--confirm-default-hasher`."
---

## Cause

`nextly users:clear-plaintext-passwords --apply` was run without `--confirm-default-hasher`.

The command recognises the hashes of core's bcrypt and of the `auth.passwordHasher` in `nextly.config.ts`. A hasher passed to `getNextly` in code, or one your app used before, can store hashes that look like plain text to this command, and clearing them would lock those people out. So `--apply` also needs `--confirm-default-hasher`, your statement that every stored password was written by core's bcrypt or by the configured hasher. Nothing was changed.

## Fix

- Run `nextly users:clear-plaintext-passwords` without `--apply` to see how many accounts it would clear.
- If no other `passwordHasher` ever wrote a password, run `nextly users:clear-plaintext-passwords --apply --confirm-default-hasher`.
