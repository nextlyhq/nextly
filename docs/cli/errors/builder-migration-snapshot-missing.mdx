---
title: BUILDER_MIGRATION_SNAPSHOT_MISSING
description: "A migration file the Schema Builder wrote has no snapshot beside it, so `nextly migrate` does not apply it."
---

## Cause

A migration file the Schema Builder wrote has no snapshot beside it, so `nextly migrate` does not apply it.

A file an earlier Schema Builder wrote is ignored by every command when it carries the Builder's whole signature: its name (13 digits, then `create`, `update`, `i18n`, `status` or `drop`, then the entity), no snapshot beside it, none of the lines `migrate:create` writes, and statements that change only that entity's own tables. A file with the Builder's name and no snapshot that does not carry the rest of the signature, for example one that changes another collection's table or a table nothing declares, is not recognised as an earlier Builder's. `nextly migrate` and a production boot refuse it before changing anything, naming the part of the signature it lacks, rather than running statements no snapshot checks. `nextly migrate --dry-run` names it too.

## Fix

- If the change is wanted and not yet in a migration, delete the file the Why line names, run `nextly migrate:create --name=<name>`, which writes the same change as a migration with its snapshot, and commit the `.sql` file and its snapshot from `meta/`.
- If the change is already in a migration, or not wanted, delete the file.

Keep the files an earlier Builder wrote in the folder until the first `nextly migrate` after upgrading has run: that run records which ledger rows are theirs. They may be deleted after it.

See [Production migrations](/docs/guides/production-migrations).

## Example

```text
✗ nextly migrate does not apply a file with a Schema Builder name that is not recognised as an earlier Builder's: 1761732000000_update_posts.sql, which has a statement on a table that is not its own entity's, or one that cannot be read.
  Why:  1761732000000_update_posts.sql was written by the Schema Builder and has no snapshot beside it (meta/1761732000000_update_posts.snapshot.json), so nothing says what the database should look like once it has run.
  Next: Replace it with the migration `nextly migrate:create` writes for that change: delete 1761732000000_update_posts.sql, run `nextly migrate:create --name=<name>`, and commit the .sql file and its snapshot; or delete it, if the change is already in a migration or not wanted.
  Docs: https://nextlyhq.com/docs/cli/errors/builder-migration-snapshot-missing  (BUILDER_MIGRATION_SNAPSHOT_MISSING)
```
