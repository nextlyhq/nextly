---
title: MISSING_SNAPSHOT
description: "A migration file has no snapshot file beside it in `meta/`."
---

## Cause

A migration file has no snapshot file beside it in `meta/`.

`nextly migrate:create` writes a snapshot beside each migration it generates, in `meta/`, describing the schema once it has run. This file has none: it was added by hand, its snapshot was deleted, or it predates snapshots.

A blank migration (`nextly migrate:create --blank`) has no snapshot by design, and `nextly migrate:check` accepts it. It recognises one by either of two lines in the file: the `-- Parent:` line of its header, or the template's own line, `-- This is a blank migration file for custom SQL.`. A file with neither is held to its snapshot.

## Fix

- Restore the snapshot from version control if it was deleted.
- For SQL you wrote yourself, in a file no database has applied yet: re-create it with `nextly migrate:create --blank` and copy the SQL across, then delete the old file.
- For SQL you wrote yourself, in a file a database has already applied: keep the file's name, since under a new one the database would run it again. Add the line `-- This is a blank migration file for custom SQL.` to its header. `nextly migrate` then stops on the edited file (`MIGRATION_TAMPERED`) until you accept the edit on every database that has applied it:

  ```bash
  nextly migrate:resolve --applied <file> --skip-verify
  ```

- Otherwise delete the file.

See [Production migrations](/docs/guides/production-migrations).

## Example

```text
✗ `20261020_120000_add_posts.sql` has no paired snapshot file in /home/you/app/migrations/meta.
  Why:  Nothing is at `20261020_120000_add_posts.snapshot.json`, which `migrate:create` writes beside every migration it generates, and the file does not say it is a blank migration, which has none; a migration generated before snapshots were written has none either.
  Next: Restore the snapshot if it was deleted. For SQL you wrote yourself: if no database has applied the file, re-create it with `nextly migrate:create --blank` and copy the SQL across; if one has, add the line `-- This is a blank migration file for custom SQL.` to its header instead, then accept the edit with `nextly migrate:resolve --applied 20261020_120000_add_posts.sql --skip-verify` on every database that has applied it.
  Docs: https://nextlyhq.com/docs/cli/errors/missing-snapshot  (MISSING_SNAPSHOT)
```
