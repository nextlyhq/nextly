---
title: PLUGIN_MIGRATION_CHANGED
description: "A plugin's migration module has changed since it was generated, so its checksum no longer matches its content."
---

## Cause

A plugin's migration module has changed since it was generated, so its checksum no longer matches its content.

Each plugin migration module carries a checksum of its own content. The module's content no longer matches it, so the SQL that would run is not the SQL that was generated and reviewed. An edited module is refused rather than re-hashed. Nothing was applied.

## Fix

- Regenerate the module, or restore the original.
- For a module written or edited by hand, seal it with `migrationChecksum` from `@nextlyhq/plugin-sdk/schema`, as `nextly migrate:create --plugin <entry> --blank` writes it.

## Example

```text
✗ Plugin "@acme/seo" migration 20261020_120000_add_redirects: a plugin migration has been changed since it was generated.
  Why:  An edited module is refused rather than re-hashed, so the SQL that runs is the SQL that was reviewed. Nothing was applied.
  Next: Regenerate it, or restore the original. A module written or edited by hand is sealed with `migrationChecksum` from `@nextlyhq/plugin-sdk/schema` — `checksum: migrationChecksum(content)` over the module without its checksum — which is the form `nextly migrate:create --plugin <entry> --blank` and `--no-transaction` write.
  Docs: https://nextlyhq.com/docs/cli/errors/plugin-migration-changed  (PLUGIN_MIGRATION_CHANGED)
```
