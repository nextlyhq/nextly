---
title: UPGRADE_WORK_MOVED
description: "`nextly upgrade` was run for the database work it used to do, which `nextly migrate` and `nextly i18n:convert-zoned-dates` now do, so it changed nothing."
---

## Cause

`nextly upgrade` was run for the database work it used to do, which `nextly migrate` and `nextly i18n:convert-zoned-dates` now do, so it changed nothing.

Earlier releases used `nextly upgrade` to bring stored data up to date. That work has moved. `nextly migrate` now hashes passwords stored before this release, removes passwords kept in version history and converts roles holding a retired manage permission, once its migrations have applied. `nextly i18n:convert-zoned-dates` converts translated date columns kept with a time zone. Run without `--reconcile-core`, `nextly upgrade` opens no database, changes nothing and exits 1, so a deploy script that still calls it fails here instead of passing with the work undone. Its `--confirm-backed-up` and `--force` flags no longer do anything.

## Fix

- Replace `nextly upgrade` in your deploy with `nextly migrate`. Where no terminal is attached, pass `--backup-confirmed` once the database is backed up; the flag is ignored when there is nothing to change.
- A development database with no migrations gets the same work from `nextly db:sync`.
- If a start or `nextly migrate` names a date column with a time zone, run `nextly i18n:convert-zoned-dates` once the release serves every instance.

## Example
