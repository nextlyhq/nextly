---
title: PLUGIN_SCHEMA_BEHIND
description: "In production, a plugin expects a schema version its applied migrations have not reached."
---

## Cause

In production, a plugin expects a schema version its applied migrations have not reached.

A plugin declares the `schemaVersion` its code expects. The database's version is the newest `schemaVersion` among the plugin's migrations recorded as applied, and in production a plugin does not start ahead of its tables. Development warns instead.

### Refused for consent

A start that runs its own migrations (`db.runMigrationsOnBoot`) applies none of them when one would delete data and no data-loss consent covers the deletion. Nothing is deleted, and every plugin with a pending migration stays behind. The error then says so in place of the commands above, which would be refused the same way: it lists each migration refused (a plugin's module by the name the ledger records it under, `plugin:<plugin>/<module>`), with what it deletes, and ends with the consent to give.

```text
✗ The plugin "@acme/seo" expects schema version 3, and the database has 2, because this start did not apply its pending migrations.
  Why:  Deleting data needs consent, and nobody can be asked (no terminal, CI, or --non-interactive).
        This would delete:
        plugin:@acme/seo/20261020_120000_add_redirects:
        - column seo_pages.summary (3 non-empty values)
        Nothing was changed.
  Next: To consent: start with NEXTLY_ACCEPT_DATA_LOSS=seo_pages.summary, or run "nextly migrate --accept-data-loss=seo_pages.summary".
  Docs: https://nextlyhq.com/docs/cli/errors/plugin-schema-behind  (PLUGIN_SCHEMA_BEHIND)
```

The migration refused is not always the plugin's own: one refusal stops the whole run, so the listing can name an app migration or another plugin's module.

## Fix

- Run `nextly migrate` to apply the plugin's pending migrations, or `nextly plugins install <name>`.
- Where the error lists deletions, read them first. To let them run, start again with `NEXTLY_ACCEPT_DATA_LOSS` set to the value the error names, or run `nextly migrate --accept-data-loss=<value>` before the start. To keep the data, take the deletion out of the migration the error lists, which may be the app's own or another plugin's.

## Example

```text
✗ The plugin "@acme/seo" expects schema version 3, and the database has 2.
  Why:  The applied version is the newest `schemaVersion` among the plugin's migrations recorded as applied, and production does not start a plugin ahead of its tables.
  Next: Run "nextly migrate" or "nextly plugins install @acme/seo".
  Docs: https://nextlyhq.com/docs/cli/errors/plugin-schema-behind  (PLUGIN_SCHEMA_BEHIND)
```
