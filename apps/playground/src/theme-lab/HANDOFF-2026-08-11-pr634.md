## 6. Hard-won knowledge — do not re-derive

1. **A stub that does not falsify may be a bad stub, not an inadequate test.** Three times this
   session: one silently half-applied (removed an attribute, left its comment); one changed a value
   the code under test never reads; one exposed a genuinely missing assertion. Check the stub landed
   AND that it disables a real input before concluding anything.
2. **`git push` reporting `! [remote rejected] … cannot lock ref` can mean the push already
   succeeded.** Always settle it with `git ls-remote` against `git rev-parse HEAD`.
3. **An exit code from a pipeline is the last command's.** `... | tail` returns tail's status. Two
   wrong readings came from this.
4. **`packages/ui` typechecks ZERO test files** (`tsc --noEmit --listFiles | grep -c '\.test\.'` =
   0). Every "typecheck clean" claim excludes them. Task 167, owned by the styling lane at socket
   82376 — not this lane's to fix, but do not claim coverage you do not have.
5. **Tokenise, do not scan.** Five rounds of false positives in the ink check came from delimiter
   assumptions; the silent one skipped the LAST utility in every class string, where `dark:`
   overrides live. Class attributes are whitespace-delimited by definition.
6. **`^a|b|c$` anchors only the outer branches.** Group before anchoring.
7. **The lab defaults to the SHIPPED theme now** (`SHIPPED_THEME` sentinel, applies no
   `data-theme`). The old handoff said to clear `localStorage["nextly-theme-lab"]` to see the
   shipped theme; that was wrong and is fixed.
8. **A sentinel needs a test that it cannot collide with a real value.** Ours would have made a real
   theme selectable, report itself applied, and apply nothing.
9. **An exception should carry a test for its own precondition** (`--font-inter` in
   `admin-token-reachability`), so it cannot outlive its reason.
